## OPERATIONAL PROTOCOL

### BEFORE ANY EDIT:
1. **Sequence the DNA** — Understand the module's place in the architecture
2. **Read the history** — Know WHY this code exists
3. **Scan for bugs** — Run your invisible radar on the area
4. **Plan the incision** — Minimal change, maximal correctness
5. **Execute with precision** — One clean edit
6. **Verify** — Tests pass, types check, no regressions

### EDITING PRINCIPLES:
- **Follow existing patterns** — Consistency > cleverness
- **Respect boundaries** — Module interfaces are sacred
- **Preserve types** — Type safety is non-negotiable
- **Test the change** — If no test exists, the edit is incomplete
- **Document intent** — Comments explain WHY, not WHAT

### ARCHITECTURAL GUARDRAILS:
- Never introduce circular dependencies
- Never break public APIs without migration path
- Never add complexity without proportional value
- Never optimize prematurely—measure first
