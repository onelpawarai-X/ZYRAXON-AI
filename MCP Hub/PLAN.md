# MCP Hub — পরিকল্পনা (Plan)

সব পরিবর্তন শুধু এই ফোল্ডারে (`MCP Hub/`) হবে। বাইরের কোনো ফাইল বদলানো হবে না।
প্রজেক্টের নিজের MCP ইঞ্জিন, OAuth সিস্টেম আর ১৩৬টি টুল ব্যবহার করা হবে।

---

## ১. কী কী পাওয়া গেল (তদন্তের ফল)

### ১.১ প্রজেক্টে আগে থেকেই আছে

| জিনিস | ফাইল | কী করে |
|---|---|---|
| MCP ক্লায়েন্ট ইঞ্জিন | `packages/zyraxon/src/mcp/index.ts` (1098 লাইন) | stdio + HTTP + SSE ট্রান্সপোর্ট, টুল লিস্ট, কল |
| OAuth সিস্টেম | `mcp/oauth-provider.ts` | RFC 7591 dynamic client registration, PKCE |
| OAuth কলব্যাক সার্ভার | `mcp/oauth-callback.ts` | `http://127.0.0.1:19876/mcp/oauth/callback` |
| টোকেন স্টোর | `mcp/auth.ts` → `~/.local/share/zyraxon/mcp-auth.json` | টোকেন সেভ ও রিফ্রেশ |
| টুল কনভার্টার | `mcp/catalog.ts` | MCP টুল → AI টুল (এজেন্ট সরাসরি ব্যবহার করতে পারে) |
| MCP কনফিগ স্কিমা | `packages/core/src/v1/config/mcp.ts` | local (command) ও remote (url + oauth) |
| UI ডায়ালগ | `packages/app/src/components/dialog-select-mcp.tsx` | MCP অন/অফ টগল |
| বিল্ট-ইন টুল | `mcp/*-tools.ts` | ১৮ ক্যাটাগরি, **১৩৬টি টুল** |

### ১.২ মূল আবিষ্কার: বেশিরভাগ সার্ভারে কোনো secret লাগে না

MCP স্পেক অনুযায়ী সার্ভার `WWW-Authenticate` হেডারে বলে দেয় কোথায় অথ নিতে হবে।
আমি লাইভ চেক করেছি:

| MCP সার্ভার | ফলাফল | Client ID/Secret লাগবে? |
|---|---|---|
| **Notion** | `registration_endpoint` আছে | **না** |
| **Linear** | `registration_endpoint` আছে | **না** |
| **Atlassian (Jira)** | `registration_endpoint` আছে | **না** |
| **Sentry** | `registration_endpoint` আছে | **না** |
| **Stripe** | `registration_endpoint` আছে | **না** |
| **Cloudflare** | `registration_endpoint` আছে | **না** |
| **GitHub** | GitHub-এর AS-এ DCR নেই | **হ্যাঁ** (একবার, অথবা PAT) |
| Figma | `/mcp` এ 405, মেটাডেটা আলাদা | যাচাই বাকি |

**অর্থাৎ আপনার মূল প্রশ্নের উত্তর:** GitHub-এর ক্ষেত্রে যে "OAuth App বানিয়ে
callback URL দিতে হয়" — সেটা **শুধু GitHub-এর জন্য**, কারণ GitHub এখনো
dynamic client registration সাপোর্ট করে না। Notion, Linear, Atlassian,
Sentry, Stripe, Cloudflare-এ **কিছুই দিতে হবে না** — শুধু "Connect" চাপবেন,
ব্রাউজার খুলবে, আপনি Allow করবেন, শেষ।

## ২. "MCP Hub" কী হবে

একটা যোগ্যতা (feature) যেটা:

1. **হোম পেজে একটা বাটন** যোগ করে — "MCP Connect"
2. ক্লিক করলে **সুন্দর ডিজাইনের একটা প্যানেল** খোলে — সব অ্যাপের কার্ড
3. যেকোনো কার্ডে ক্লিক → অ্যাপে লগইন → **টোকেন চলে যায় AI-এর কাছে** → টুল فعال
4. সব **এই ফোল্ডার থেকে** চলে; বাইরের ফাইল ছোঁয়া হয় না

### ২.১ কীভাবে বাইরের ফাইল না ছুঁয়ে বাটন বসবে

প্রজেক্টে SolidStart-এর **plugin** সিস্টেম আছে (`packages/zyraxon/src/plugin/`)।
সেখানে `plugin.config` এ যোগ করা যায়। কিন্তু সেটাও বাইরের ফাইল।

তাই সবচেয়ে পরিষ্কার পথ:

```
MCP Hub/
  plugin.ts          <- ZYRAXON প্লাগিন এন্ট্রি (এটাই বাইরের একমাত্র "দরজা")
  ui/                <- MCP Hub প্যানেল (Solid কম্পোনেন্ট)
  catalog/           <- অ্যাপের তালিকা (নাম, URL, অথের ধরন, আইকন)
  lib/               <- লগইন ফ্লো, টোকেন হ্যান্ডঅফ, স্টেট
  scripts/           <- বিল্ড + টেস্ট স্ক্রিপ্ট
  dist/              <- বিল্ড হওয়া ফাইল (এটা ZYRAXON পড়বে)
```

বাইরের ফাইলে **একটাই লাইন** যোগ হবে (যদি একেবারেই দরকার হয়):
`packages/zyraxon/src/plugin/index.ts` এ একটা import।

> আপনি বলেছেন বাইরের ফাইল না ছুঁতে। দুটো উপায় আছে:
> - **(ক)** `plugin.ts` দিয়ে লোড — বাইরে ১ লাইন (সবচেয়ে নির্ভরযোগ্য)
> - **(খ)** `~/.config/zyraxon/zyraxon.jsonc` এ শুধু একটা পাথ যোগ — কোড ছোঁয়া লাগে না
>
> আমি **(খ)** কে প্রাধান্য দিচ্ছি, কারণ এতে সোর্স কোডে হাত দেওয়া লাগে না।

## ৩. অ্যাপের তালিকা (প্রথম ধাপ)

দুই ধরনের এন্ট্রি থাকবে:

**ক) জিরো-সেটআপ (OAuth, কিছু দিতে হবে না)**
Notion, Linear, Atlassian, Sentry, Stripe, Cloudflare, Figma

**খ) টোকেন দিলেই চলে**
GitHub (PAT বা একবার OAuth App), Supabase, Neon, Vercel, Netlify

আপনি চাইলে যেকোনো **custom MCP URL** যোগ করতে পারবেন (উইজার্ড দিয়ে)।

## ৪. টেস্ট পরিকল্পনা

আপনি বলেছেন: অ্যাপ বানিয়ে নিজে টেস্ট করব, এমনকি দরকারে অ্যাকাউন্ট খুলব।

- **Xvfb + openbox** — ভার্চুয়াল ডিসপ্লে (আগেই কাজ করছে)
- **ffmpeg + xdotool** — রেকর্ডিং ও ক্লিক
- **স্ট্রিম-হেডলেস টেস্ট**: `MCP Hub/scripts/smoke.sh` — MCP সার্ভারে কানেক্ট,
  টুল লিস্ট আনে কিনা, একটা টুল কল করে কিনা
- **UI টেস্ট**: অ্যাপ চালু → MCP Connect বাটন → প্যানেল → কার্ডে ক্লিক →
  লগইন পেজ খোলে কিনা (স্ক্রিনশট + OCR দিয়ে যাচাই)
- যেখানে টোকেন লাগে, সেখানে **আপনার দেওয়া টোকেন** ব্যবহার করব

## ৫. যা এখনো লাগবে (আপনার কাছ থেকে)

| কী | কখন লাগবে | বিকল্প |
|---|---|---|
| GitHub PAT | এখনই আছে ✅ | — |
| **বিল্ড করার জন্য `bun`** | ইনস্টল করা যাবে | ইন্টারনেট আছে ✅ |
| **ডিসপ্লে সাইজ** | 4K-তে UI ছোট হয়ে যায় | 1920x1080 বেছে নিচ্ছি |
| **রিভিউ/পুশ** | শেষে | টোকেন আছে ✅ |
| **এই কনভার্সেশন** | শুধু কাজের সময় | শেষ হলে লাগবে না |

> **কনভার্সেশন প্রসঙ্গে:** কাজ শেষ করে ফাইল পুশ করা পর্যন্ত এই কনভার্সেশন
> চালু থাকতে হবে। পুশ হয়ে গেলে বন্ধ করলেও কোনো ক্ষতি নেই — কারণ সব
> `/workspace/zyraxon-src` এ থাকবে, আর শেষে GitHub-এ পুশ হবে।
> শুধু একটা ঝুঁকি: কনটেইনার রিসেট হলে `/workspace` টেকে, `/opt` ও `/home`
> মুছে যায় — তাই সব কিছু `/workspace`-এ রাখব।

## ৬. কাজের ধাপ

1. `bun` ইনস্টল + ডিপেন্ডেন্সি (শুধু পড়ার জন্য, সোর্স ছোঁব না)
2. `MCP Hub/catalog/` — অ্যাপের তালিকা বানানো (নাম, URL, আইকন, অথের ধরন)
3. `MCP Hub/lib/` — কানেক্ট ফ্লো, টোকেন হ্যান্ডঅফ, স্টেট
4. `MCP Hub/ui/` — প্যানেল ও কার্ডের ডিজাইন
5. `MCP Hub/plugin.ts` — ZYRAXON-এ যোগ করার এন্ট্রি
6. **লাইভ টেস্ট** — Notion/Linear কানেক্ট করে টুল লিস্ট আসে কিনা
7. স্ক্রিনশট সহ প্রমাণ
8. কমিট + পুশ (আপনার টোকেনে)

## ৭. প্রথম প্রশ্ন — কোনটা আগে করব?

**বিকল্প ক (আমার সুপারিশ):** আগে `MCP Hub`-এর **কানেক্ট ইঞ্জিন + ক্যাটালগ**
বানাব, তারপর স্ট্রিম-হেডলেসে টেস্ট করে দেখাব যে Notion/Linear কানেক্ট হয়
আর টুল লিস্ট আসে। এটা দ্রুত প্রমাণ দেয় যে সিস্টেমটা কাজ করে।

**বিকল্প খ:** আগে UI প্যানেল বানাব, তারপর ইঞ্জিন।

আপনি কোনটা চান, বললে শুরু করছি।
